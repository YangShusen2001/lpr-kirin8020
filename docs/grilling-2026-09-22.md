# 需求对齐记录（2026-09-22）

> 三轮提问的记录。**这份记录本身是一份「人机协作纠偏」的实例** ——
> 它展示了人如何用提问把一个模糊的需求收敛成可执行的范围，
> 以及 AI 在过程中**被纠正了三次**。
>
> 产出：`docs/roadmap.md`（执行依据）。
> 用途：既是对齐留痕，也是求职叙事里「如何让 agent 纠偏」的真实素材。

---

## 为什么要做这一轮

用户原话（节选）：

> 我也不知道应该如何去评价……这件事情还是从前交给你，你继续提问，我点头了，你就去干就行。
> ……还是老样子，你问我，我回答，直到我们两个需求对齐。

⇒ 用户明确要求**用提问把需求问出来**，而不是让 AI 猜。

---

## 第一轮：先纠正两个事实前提

在提问之前先纠正了用户的两个错误前提 —— **这是提问的前提，不是提问本身**：

| 用户的假设 | 事实 |
|---|---|
| 「GPU 我们还没弄呢」 | **弄完了**：Maleoon 920C 探针通过，ncnn-Vulkan `vkLayers=218/218`、数值保真；但比 CPU 慢 2–5 倍 |
| 「线上演示页要从零做」 | **已有三张成品**：`lpr-showcase/index.html` / `demo.html` / `mobile.html`，纯前端零网络请求 |

**教训**：用户的"我以为没做"，和"真的没做"，是两件事。**先查再问。**

### 第一轮的 8 个问题与结论

| # | 问题 | 结论 |
|---|---|---|
| Q1 | "玩具感"具体指什么（abcde 多选） | 用户：**都有**，且把评价权交给我 |
| Q2 | 仓库整合成什么形态 | 用户：**双仓库可以，但必须改**；实验多 + GPU 不行都要写上，**非常非常精简**（面试官不会看太久） |
| Q3 | GPU 补到什么程度 | 用户：**既不是 A 也不是 B** —— 重新按 Matt 的流程去搜官方资料；**不行才放弃** |
| Q4 | 英文产出的形态与数量 | 用户：**IEEE 论文 + NPU 调用指南**；若 GPU 能与 NPU 结合 → 归入「麒麟 SoC 系列测试」 |
| Q5 | 演示的目标场景 | 用户：**主要是 B**（发给面试官自己看）；网页里嵌**可实时点击的手机** |
| Q6 | 演示页改造还是重做 | 用户：**改造**，不再从零造轮子 |
| Q7 | 展示页定位 | 用户：**同意求职叙事**；并澄清本项目**不是** agent 开发 |
| Q8 | AI agent 纠偏叙事落到哪一层 | 用户：**同意 B+C 轻量版**；并追问 Jev 能不能模拟决策 |

### 用户在这一轮提出的重要批评

> 这个项目一路做下来，我发现我们真正去搜资料很少，都是自己在埋头苦干，
> 这是一个非常非常非常不好的一个做法。

**AI 的回应**：立刻去做了一次针对性检索（GPU 官方通路），当场的回报见下。

## 第二轮：检索带来的三个改变

### 改变一：GPU 结论被升级

一次官方资料检索，把 GPU 那一格从「我们测出来慢」升级为：

- **CANN / NNRt / MindSpore Lite 的官方计算单元清单里没有 GPU**
- **MindSpore Lite 的 GPU 回落是平台设计**（官方构建文档：`MSLITE_GPU_BACKEND` 在非
  OpenHarmony 才有效；「目前 OpenHarmony 系统仅支持 CPU 推理，不支持 GPU 推理」）
- **ncnn 官方 FAQ 自己就说** ARM 手机上 GPU 慢于 CPU 是常态
- 唯一没被排除的路：HiAI Foundation（但 DDK 支持列表不含 8020）

⇒ 产出 `docs/notes/gpu-official-verdict.md`。

### 改变二：Jev 的定位被纠正

用户想用 Jev 做 Computer Use。检索结果**纠正了用户的瓶颈判断**：

- OSWorld-Human 实测：**规划 53.5–74.6% + 反思 22.5–33.6%，截图与动作只占 1.1–3.3%**
- ⇒ **该优化的是"减少模型调用次数 + 压缩上下文"，不是"换更快的点击"**
- Jev 无视觉（官方原文），**做不了感知层**
- **HarmonyOS 手机端 Computer Use 方向不成立**：无障碍 API 自 12 起全部 deprecated
  且无三方替代（华为开发者问答：「由于安全原因…不再对三方开放了」）

⇒ 产出 `on-device-decision-model-survey.md` 附录二。

### 改变三：一个被忽略的资源浮出水面

用户提到**有云手机资格（麒麟 9050 Pro + 整个麒麟系列）**。
这直接对应 ADR-0007 当初降级 RQ2 的**唯一理由**（门店演示机不可得）。

⇒ 成为执行顺序的第 1 步。

### 第二轮的 6 个问题与结论

| # | 问题 | 结论 |
|---|---|---|
| Q1 | 云手机能不能解锁 RQ2 | 用户：能装 HAP；thermal 待测；真机可测。**但没看懂我的建议**，要求重述 |
| Q2 | "玩具感"的最小补法 | 用户：**同意**（先做重复，基线看能不能找到） |
| Q3 | 演示页里的"手机"跑什么 | 用户：理解成"**程序写死了，让他点击模拟整体使用**"，类比"色块占位" |
| Q4 | 鸿蒙 UI 重设计到什么程度 | 用户：**整体重新设计**；简单清晰实用；**尺寸参数是硬性要求** |
| Q5 | AI agent 那条桥搭在哪 | 用户：**先留着** |
| Q6 | 红果/抖音项目要不要进作品集 | 用户：**进**，但它是**下一个项目**；**现在先完成论文与识别** |

| # | 问题 | 结论 |

| Q1 | 云手机最小验证做不做 | 用户：**一定要做** |

| Q4 | 展示页 5 字段 | 用户：**暂时按你说的，不满意再改** |
| Q5 | 执行顺序 | 用户：**同意** |
| Q6 | 语言分工 | 用户：**只有论文是英文，其他全写中文**（"没人会看的"） |

### ⚠️ AI 在这一轮被纠正了一次

我在第二轮把语言分工理解成「技术报告 + NPU 指南 = 全英文」。
用户明确纠正：**只有论文英文，其余全中文**。

**这是一个典型的"AI 过度外推"** —— 我从"不要中文稿（论文）"外推成了
"所有技术文档都英文"，而用户的真实意图只是论文。**外推范围越大，越要回问。**

## 这一轮的方法论沉淀

| # | 教训 | 触发它的事件 |
|---|---|---|
| 1 | **先查再问**：用户的"我以为没做"和"真的没做"是两件事 | GPU 其实做了；演示页其实已有成品 |
| 2 | **先搜一手资料，再动手实测**，两者并行 | 用户批评"埋头苦干、不搜资料"；一次检索就把结论升级了 |
| 3 | **外推范围越大，越要回问** | 我把"论文不用中文"外推成"技术文档全英文"，被纠正 |
| 4 | **纠正用户的前提，比顺着他的问题答更有价值** | 用户的瓶颈判断（截图慢）被论文数据证伪 |
| 5 | **把"我以为的答案"写出来让用户点头/否决**，比开放式提问高效 | 三轮回合全部采用"选项 + 我的推荐"格式 |
