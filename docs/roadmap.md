## 3. 每步的验收标准

### 第 1 步 · 云手机最小验证

**做法**：编译一个**只读** HAP（只读 thermal + 落点 + 跑一次 Vulkan 探针，不写任何东西），
装到云手机跑 5 分钟。

**三个必答问题**：

| # | 问题 | 为什么重要 |
|---|---|---|
| 1 | 能装 HAP 吗 | 用户已确认 ✅，仍需实测一次 |
| 2 | `thermal.getThermalLevel()` / `batteryInfo` 返回什么 | **RQ4 完全依赖这两个 API**；若返回常量或异常，云手机不能用于热特性 |
| 3 | Vulkan 探针拿到的是**真 GPU 还是虚拟化的** | 若是虚拟化，**GPU 相关结论在云手机上全部不可用** |

**验收**：三个问题都有确定答案，且明确写出「云手机能用于 A/B/C，不能用于 D/E/F」。

**分支**：

- 三个全过 → RQ2（跨 SKU 扩展律）复活，论文加一章
- 只有 1 过 → 云手机仅用于"跑通功能"，不用于采性能数据
- 1 都不过 → 记为「云手机路线不可用」并说明

### 第 2 步 · RQ4 拆两次独立运行

**做法**：跑两次各 40 轮（约 25 分钟），中间**完全重启 App**（清空 thread_local scratch），
报告轮间区间而不是单点。

**验收**：给出两次运行的漂移量（如 `+26.9% / +X%`），并说明是否复现。
**若第二次不复现，如实写"未复现"** —— 这比强行报一个数字有价值。

### 第 3 步 · 论文英文稿补完

**必做**：

1. 新增 GPU 章节（素材见 `docs/notes/gpu-official-verdict.md`）
2. Related Work 从 5 篇扩到 15–25 篇，补两条线：移动端 NPU 异构调度、算子委托/回落
3. 基线对比尝试（找不到就写"未做" + 原因）
4. 加入第 2 步的两次运行结果
5. 所有跨栈跑分表**逐表加「框架」列**（ADR-0002 要求，`evidence-index.md` §1.3 登记为待落实）

**验收**：`tools/verify_published_numbers.py` 全通过；论文中每个数字都能在
`docs/evidence-index.md` 找到。

### 第 4 步 · NPU 调用指南（中文）

**形态**：**按"你会踩的坑"组织**，每条四段：现象 → 根因 → 正确做法 → 可复现的最小验证。

**已有素材**（不新造）：

- 落点自证三件套（`req=` / `LANDED=` / `fallback=` + 张量指纹）
- 会话必须常驻（析构 cppcrash）
- 固定 batch = 1（动态 batch 构图失败）
- 非 ASCII 路径（hvigor `00306003`、OMG 输出路径）
- `-O0` 静默覆盖 `-O3`（延迟虚高 1.7–4×）
- FULL_QUANT 整图静默回退 / WEIGHT_QUANT 可用
- 算子覆盖边界（独立委托 vs 融合携带；CANN 51/51）
- GPU 无官方通路（本文档 §1 的 GPU 结论）

**验收**：每条坑都有一个**可执行的最小验证脚本或命令**，读者能自己复现。

### 第 5 步 · 鸿蒙 App 重设计

**6 块组件（已确认，不再增加）**：

| 区块 | 组件 |
|---|---|
| 输入 | 相机实时 / 相册选图 |
| 参数 | 输入尺寸 320 / 480 / 640 / 720 |
| 参数 | 后端档位 CPU / NPU 切换 |
| 输出 | 车牌串 + 牌色 + 逐字符置信度 + 检测框 |
| 输出 | **落点自证面板**（LANDED / 分段耗时 / 指纹） |
| 移出 | 探针控制台（20+ 按钮）→ 独立页，主界面一个不留 |

**做法**：骨架先行（色块占位）→ 用户看结构 → 再填真实数据。

**验收**：主界面能在 30 秒内演示完三个场景；探针控制台不出现在主界面。

### 第 6 步 · 演示页改造 + 展示页

**演示页**（改造 `lpr-showcase/index.html` / `demo.html` / `mobile.html`）：

- 嵌入一个可点击的手机样式容器
- 三个场景共 40 秒：
  1. 传图 → 出结果（10 s）
  2. 切换后端 CPU ↔ NPU → 看落点与延迟变化（20 s）
  3. 打开落点自证面板 → 看分段耗时（10 s）

**展示页**：求职叙事定位。每个项目 **5 个字段**：
一句话主张 / 三个数字 / 技术栈 / 状态（完成·进行中）/ 链接。

**验收**：面试官能**自己上传一张车牌照片**看到结果（这是任何录屏都替代不了的）。

## 5. 一条贯穿全程的纪律

**先搜一手资料，再动手实测。** 两者并行，不是后者替代前者。

这条纪律来自用户的一次批评（原话）：

> 我们真正去搜资料很少，都是自己在埋头苦干，这是一个非常非常不好的做法。

它当场的回报：一次针对性的官方检索，把 GPU 那一格从
「我们测出来慢」升级为「官方没提供这条路，根因是 OpenHarmony 没编译 GPU 后端」，
还顺带找到一条没被排除的路（HiAI Foundation）。
