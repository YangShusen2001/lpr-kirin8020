# ADR-0008 · 探针控制台重设计：单人化的实验工作台

- **状态**：已接受
- **日期**：2026-09-22
- **前置**：ADR-0004（App 单后端 MS Lite）、ADR-0007（范围收口 RQ3+RQ4）
- **证据**：`LprDemo/entry/src/main/ets/pages/Index.ets`（重写后 ~3450 行）、
  `pages/CameraPage.ets`（2140 行，**已删除**）

## 问题

现控制台是**调试期逐条加按钮**堆出来的，26 个探针按钮平铺在一张长滚动页上，两个 tab，
没有分组、没有状态反馈、没有结果归纳。三个具体毛病：

1. **看不了** —— 结果只往一个 `lines: string[]` 里 append，长跑之后要一直往上翻；
   没有"这次跑完了没有 / 跑到第几项 / 结论是什么"的区分。
2. **认不出** —— `算子对撞` / `CANN 探针` / `三后端槽位` / `ncnn/Vulkan` 这些名字是**我自己
   当时的思路**，不是实验编号。隔一周回来看不出哪个对应论文哪一节。
3. **跑不动** —— 要拿到一组能进论文的数据，得手动点 5–8 个按钮、每次盯着它跑完。
   云手机上无人值守，点不了。

同时 `CameraPage.ets`（2140 行）在**目标环境上不可用**：云手机官方明文不支持相机
（`docs/guides/npu-pitfalls-build-and-env.md` 同源结论）。它现在只是构建负担。

## 决策

**把控制台从「探针按钮墙」改成「实验工作台」，以 RQ 编号组织，默认一键跑完。**

### 三条判据（决定每个探针的去留）

1. **论文要引用它的数据** → 留，并归到所属 RQ 下
2. **只是当时为了搞清某个机制而做的调试** → 砍（结论已写进文档/ADR，代码不必留）
3. **依赖相机的** → 砍（目标环境没有相机）

### 保留的实验（按 RQ 分组）

| 组 | 实验 | 产出 | 去向 |
|---|---|---|---|
| **一键全跑** | 编排下面全部 | 全部日志 | 主入口 |
| **RQ3 · 延迟分解** | 三模型 × 四后端矩阵（warmup 5 + 正式 30 次 p50） | `matrix.log` | RQ3 主数据 |
| | 异构放置对照（全 NPU vs det-CPU + rec-NPU） | `matrix.log` | RQ3 核心主张 |
| **RQ4 · 热特性** | 长循环热漂移（≥20 min，替代"NPU 漂移"单点） | `rq4_thermal.log` | RQ4 主数据 |
| **精度** | 识别器裸测（crops 1000 张） | `crop_bare.log` | 精度侧 |
| | 落点 A/B（det / rec 分角色） | `crop_ab_*.log` | 精度侧 |
| | 场景 A/B（ccpd / green） | `scene_*_*.log` | 精度侧 |
| **T8 · 工具链联合属性** | 算子对撞（51 探针） | `op_collide.log` | 论文亮点 |
| | CANN/OMG 探针（含 LPRNet 候选） | `op_collide.log` | 论文亮点 |

### 砍掉的（附理由）

| 砍掉 | 理由 |
|---|---|
| `CameraPage.ets` 整页 | 目标环境无相机（判据 3） |
| `枚举镜头` | 相机专用（判据 3） |
| `相机实时识别` | 相机专用（判据 3） |
| `GPU 专项` | 结论已定：MS Lite GPU 档编译期判否、静默回退 CPU；真正 GPU 通路是 ncnn-Vulkan，已并入三后端矩阵的 `gpu` 项（判据 2） |
| `ncnn/Vulkan` 独立按钮 | 同上，作为矩阵的一个后端存在即可（判据 2） |
| `三后端槽位` | 是 ncnn 通路的中间验证，结论已并入矩阵（判据 2） |
| `NPU 漂移` 单点按钮 | 被 RQ4 长循环取代 —— 单点漂移正是 `spec-portfolio.md:23` 点名的"随时可被质疑是噪声"的那个（判据 2） |
| `加载模型` 独立按钮 | 改为运行时自动加载，不该要用户记得先点（判据 2） |

**26 个按钮 → 4 组 + 1 个「一键全跑」。**

### 界面结构

深色专业仪器风（用户选定）。三区：

```
┌─────────────────────────────────┐
│ ① 顶部状态条                     │  运行态 / 进度 n/N / 当前实验名 / 计时
├─────────────────────────────────┤
│ ② 结果区（可滚动、可长按复制）    │  结构化：分组标题 + 结论摘要 + 逐条明细
│    RQ3 ▸ 3 模型 × 4 后端        │
│      det/nnrt  p50=12.4ms  ...  │
├─────────────────────────────────┤
│ ③ 操作区（底部固定）             │  [一键全跑] [分组: RQ3|RQ4|精度|T8] [清空]
└─────────────────────────────────┘
```

**要点：**
- 结果区**只保留最近一次运行的结论摘要 + 明细**，不再无限 append（解决"看不了"）。
- 每组实验名旁标 **RQ 编号**（解决"认不出"）。
- **长按结果区复制全部文本** —— 这即用户选定的导出方式（云手机 hdc 拉不了）。
- 底部固定操作区，不随滚动跑掉。

### 「一键全跑」的编排顺序

按**成本递增 + 失败可容忍**排：

1. 自动加载模型（原独立按钮）
2. RQ3 矩阵（约 5–8 min）
3. 精度三项（crops 1000 张，约 3–5 min）
4. T8 算子对撞（51 个，约 2–3 min）
5. RQ4 热循环（≥20 min，**最后跑**，因为它要求独占、且会污染热态）

第 5 步最后是硬约束：**热循环必须先于一切跑完才开始**，否则前面实验的发热会污染基线。

## 实现记录（2026-09-22 落地）

本节记录**实施阶段新冒出来的取舍** —— 设计时没预见到、写代码时才被迫定下来的。

### 1. 解析器只搬运，不换算

结果区的结构化是**纯文本→结构化的搬运**：`parseMatrixRows()` / `parseE2eRows()` /
`parseAccGroups()` / `parseT8Group()` / `parseRq4Group()` 一律**取探针写进 `lines` 的原始字符串**，
不换算单位、不做统计、不臆测缺失值。

硬约束：**缺失字段不补 0**。补 0 会凭空造出 `0%` 准确率，那是比"没数据"更坏的错误 ——
读者会以为真跑出了 0%，而实际上是探针没写这一行。

**唯一允许的统计**是 RQ4 稳态斜率：取后 2/3 轮做最小二乘，规避预热段。
这是唯一有明确物理理由的统计，其余一律原样搬运。

### 2. 算子名单改为运行时枚举

原实现硬编码 51 个 `op_*.om` 名字。实际磁盘上有 52 个 → 面板显示 51 个，
**静默漏测一个算子**，而且没有任何提示。

改为 `scanOpProbeNames(ctx)`：用 `resourceManager.getRawFileListSync('models')` 列目录，
筛 `op_` 前缀且 `.om` 结尾的，排序返回。保留 `OP_PROBE_NAMES_FALLBACK` 兜底，
但**枚举失败时会在面板上写明踩了兜底名单**（"可能与磁盘不一致"），不静默过关。

### 3. 两个编译期自检开关退休

`AUTO_SELFTEST` / `AUTO_RQ4` + `AUTO_RQ4_MINUTES` 删除，原位留注释。

理由：这两个开关的存在只是为了"装机后无人值守自动跑一遍看看"。
现在有了面板上真能点的「一键全跑」，开关的唯一理由消失了 ——
而且编译期开关有个致命缺点：**要改行为必须重新构建、重新签名、重新安装**，
在云手机/真机上这个循环是分钟级的。「一键全跑」把它降到一次点击。

### 4. 编排顺序由常量保证，不靠人记

`GROUP_ORDER = [RQ3, 精度, T8, RQ4]`，`runAll()` 按此顺序走。
RQ4 热循环**必须最后**（独占 + 污染热态基线），这一点在 ADR 里是硬约束，
现在落成了代码常量 + 面板提示行「RQ4 热循环必须最后跑」。

### 5. `ForEach` key 加 `g-` 前缀

结果组的 key 全部改成 `g-rq3` / `g-acc-crop` / `g-acc-scene-<set>-<role>` / `g-t8` 等。

ArkTS 的 `ForEach` 在 key 冲突时是**静默丢项**的 —— 不报错、不告警，只是少渲染一行。
精度组里同一场景的 `det` / `rec` 两个角色、不同数据集（ccpd / green）的组合很容易撞 key，
所以统一加前缀把命名空间隔开。

### 6. 相机线整条移除

> ⚠️ **本节已于同日部分推翻 —— 见文末《修订（2026-09-22 晚）》。**
> 相机线按用户明确要求恢复（spec：`docs/spec-vehicle-pipeline.md`）。
> 下面这段保留为历史记录，**不再是当前状态**。

- `CameraPage.ets`（2140 行）从磁盘与 git index 删除
- `main_pages.json` 只剩 `pages/Index`
- `module.json5` 删掉 `ohos.permission.CAMERA`（现在只剩 `INTERNET`）
- `string.json` 删掉 `reason_for_camera`
- `Index.ets` 删掉 `@kit.CameraKit` / `abilityAccessCtrl` / `router` 三个 import

顺带把 `requestCamera()` / `listLenses()` 也删了（它们只服务相机路径）。

### 7. 导出走系统剪贴板，不写文件

用户定的导出形态是「终端界面上直接看 + 复制」。实现为 `copyAll()`：
`pasteboard.createPlainTextData()` → `getSystemPasteboard().setData()`。

复制的内容是**三段**：① 头部（时间/分组/状态/用时）② 结构化结果（分组标题 + 每条读数）
③ **完整**原始输出。

第 ③ 段是关键：面板为了可读性只展示尾部 300 行（`RESULT_RAW_TAIL`），
但**复制必须给全的** —— 否则云端拿到的证据是不完整的。

### 8. 拍平 `Index.ets` 的工程手段

`Index.ets` 3351 → ~3450 行，重写量大，用**分片拼装**完成：
`_logic_head.ets`（逻辑与解析器）+ `_orchestration.ets`（编排）+ `_ui_new.ets`（UI）
→ `_assemble.py` 合成 `Index.ets`。拼装件在验证通过后即删。

`aboutToAppear()` 不再自动跑任何实验、不再申请任何权限 —— 进去就是一张干净的面板。

## 修订（2026-09-22 晚）：相机线部分恢复

- **状态**：已生效（T1 工单 #29）
- **触发**：用户明确要求「恢复相机实时」，并给出外部效度理由 ——
  *"我用摄像头去实时用的时候会用到，因为干扰多，得放大来看"*。
- **依据**：`docs/spec-vehicle-pipeline.md`（车辆识别流水线 spec）

### 为什么原来的判据 3 不成立

§「决策」的**判据 3（依赖相机的 → 砍）**建立在「目标环境没有相机」上。
这对**云手机**仍然成立（华为云真机官方明文不支持相机/SIM/电话/短信）。
但本项目的主验证环境是**物理真机华为 `MIA-AL00`**（HarmonyOS 6.1.0.135 / API 24），
**有相机**。ADR-0008 当时把「云手机没有相机」当成了「目标环境没有相机」——
这是范围偷换：云手机是**备选**验证环境，不是唯一环境。

### 恢复清单（逐条对应 §6）

| §6 当初的删除动作 | 本次恢复 |
|---|---|
| `CameraPage.ets` 从磁盘与 index 删除 | **从 git HEAD 恢复**（2140 行，与删除前逐字节一致） |
| `main_pages.json` 只剩 `pages/Index` | 加回 `pages/CameraPage` |
| `module.json5` 删掉 `ohos.permission.CAMERA` | 加回（含 `reason` / `usedScene`） |
| `string.json` 删掉 `reason_for_camera` | 加回 |
| `Index.ets` 删掉三个 import | **只加回 `router`** |

### 没有恢复的部分（有意）

- `@kit.CameraKit` 与 `abilityAccessCtrl` / `Permissions` **不回 `Index.ets`**。
  §6 里说「顺带把 `requestCamera()` / `listLenses()` 也删了」——实测这两件事
  `CameraPage.ets` **自己就有一份**（`requestCamera()` 在第 612 行、
  `camera.getCameraManager()` 在第 803 行）。探针台只负责**跳转**，
  权限申请与镜头枚举留在相机页内，两个页面职责不交叉。
- 往回加用不到的 import 会让 linter 报 unused，也会让读者误以为 `Index.ets` 碰相机。

### 边界声明（重要）

- **本次不触碰 ADR-0008 的 UI 重设计。** 相机入口是**新增**在深色仪器风版本上的
  （`Index.ets` 新增 `pageHeader()` @Builder，其余 `build()` 顺序不变），
  没有任何一处回退到旧浅色界面。这是 T1 票写死的验收标准。
- **`CameraPage.ets` 本次「不改造」**，按原样恢复（T1 票要求「先跑通原功能」）。

### 已知遗留（交给 T5）

`CameraPage.ets` 仍是**iOS 浅色**，而 `Index.ets` 已是**深色仪器风**；
两页互跳会有一次明显的明暗跳变。这一条**有意留到 T5**（界面工单）——
T5 本来就要改相机页的结果区（车辆框 + 车牌→车辆归属 + 两路径切换），
配色统一应当与那批改动合并做，而不是现在先刷一遍颜色、T5 再刷一遍。

**当前状态是「功能正确、视觉未统一」，不是「已完成」。**
