# ADR-0002 · 论文主张改为「落点自证 + 算子覆盖边界」

- **状态**：已接受
- **日期**：2026-09-20
- **前置**：ADR-0001（继承前期数据）
- **后续**：ADR-0003（证据标准）、ADR-0004（后端选择）、ADR-0007（范围收口）
- **证据**：`ShusenPaper/results/week3-op-matrix.md`、`ShusenPaper/paper/outline.md`、`lpr-showcase/_evidence/A17`、`A18`

## 问题

`lpr-showcase` 的论文主张是**跨语言移植保真**（把 C++/Python 参考逐行移植为 ES Module，逆向 `cv2.resize` 定点实现，达到整数缩放比下逐通道一致）。

代码全部重写后，**不再有 JS 移植版**，这个主张失去载体。新论文的核心贡献是什么？

## 决策

**主线改为「落点自证方法学 + 算子覆盖边界」，并与 `ShusenPaper` 的「独立委托 vs 融合携带」模型合并为同一篇论文。**

三条可发表的贡献：

1. **落点自证方法学**：在 NPU 利用率**不可读**的平台上（见 ADR-0003），如何证明异构后端真被用上——`LANDED=` / `fallback=` / `req=` 字段 + 张量指纹 + CPU 对照差分，三者互证。
2. **算子覆盖边界**：36 算子三信号矩阵（独立可编译 20 / 被拒 16），以及**"独立委托 vs 融合携带"**模型——被拒算子可作为 Conv 融合邻居上 NPU，孤立出现则必切子图回落 CPU。
3. **该模型的解释力**：用它解释 `lpr-showcase` 的全部异常观测（检测头翻字符、分类器 0.84×、LPRNet 分区 `NPU:2,CPU:1`），把三批独立实验统一到一个结构性原因下。

## 理由

1. **证据全部现成**。算子矩阵、roofline、5 轮套件数据、三缺陷提单链都在磁盘上；新增工作主要是 L3 流水线（RQ3）。
2. **主张强于旧稿**。"保真"证明的是"移植没写错"，而"落点自证 + 算子边界"回答的是**"为什么上了 NPU 却不快/不对"**——这是移动端 NPU 部署的真问题。
3. **与 ADR-015 同血脉**。`lpr-showcase` 最有价值的产出是"用独立第三方集抓到自己参照串的错误"；新主张把这种**自我纠错的方法学**从"参照串"推广到"后端落点"。

## 后果

- 旧论文稿（`lpr-showcase/paper/`，68 KB md + 两份独立 tex + 7 张图）**归档**，不再作为主稿；其保真章节作为**前期成果**引用。
- 论文须包含**跨栈可比性声明**：NPU 走 MindSpore Lite + NNRT，GPU 只有 ncnn-Vulkan，CPU 有 ms-cpu 与 ncnn-cpu 两套——**跨栈比较只能当量级参考，可比的是同栈内比值**。
- 跑分表**必须含「框架」列**，否则是全项目最易被攻的点。

## 边界声明

- 本 ADR **不**主张"融合携带"模型已被因果证明：现有证据是**相关性**（ResNet 内含被拒算子却整体加速）+ 分区日志（`NPU:2,CPU:1`）。要做成因果，需**同权重、逐算子插桩**的对照实验。
- 本 ADR **不**主张算子覆盖边界对 CANN 通路成立：现有矩阵是 **NNRT 通路**的；CANN 的 166 个 IR 算子清单是**文档级**证据，未在本设备逐算子实测（DDK 与 OMG 工具链**已在磁盘上**，见 [notes/toolchain-and-sources-on-disk](../notes/toolchain-and-sources-on-disk.md)，故该实测可行，只是尚未做）。
